# PRD-06: App folder picker and project-level Connect Claude

| Field | Value |
|---|---|
| Requirements covered | KB31-FR-02 (app), 05 (app); KB31-NFR-01, 02, 03 |
| ADRs | ADR-005, ADR-006 |
| Wave · Requires | 3 · PRD-01 (`shell.rs` python parts first), PRD-05 (`addProjectPanel`, `{tab}`, tokens) |
| Parallelisable | No — alone in wave 3 |

Paths are relative to `plugins/kanban/`.

## Goal
A native folder picker for Add project, reachable only by the board page on the daemon origin in the main window, and
a project-level Connect Claude that starts (or reveals) Claude with channels in the project's terminal.

## Steps
1. Tests first: cargo tests in the `scope.rs`/`shell.rs` test modules; terminal.js contract tests in their own file
   (`tests/test_ui_contract.py` belongs to PRD-05) — `app/src-tauri/src/scope.rs` (modify), `tests/test_terminal_contract.py` (create)
2. Dependency: `tauri-plugin-dialog = "2"` (the only new crate) — `app/src-tauri/Cargo.toml`, `app/src-tauri/Cargo.lock` (modify)
3. App manifest: add `pick_folder` to `AppManifest::commands` (`build.rs:4-8`); commit what tauri-build generates
   outside `gen/` (today `permissions/autogenerated/pick_folder.toml`), or nothing if it generates nothing there —
   `app/src-tauri/build.rs`, `app/src-tauri/permissions/autogenerated/**` (modify, if generated)
4. Scope: the runtime capability (`scope.rs:10-20`) adds `allow-pick-folder` and nothing from `dialog:*`;
   `terminal_allowed` (`:23-27`) is reused (or renamed `board_allowed` with the same rule) for the new command —
   `app/src-tauri/src/scope.rs` (modify)
5. Command `pick_folder(app, window) -> Result<Option<String>, String>`: re-checks window label + webview origin
   (`allowed_board`, `shell.rs:304-312`); opens the native folder dialog without blocking the main thread; returns an
   absolute path or `None`; registered in `invoke_handler` (`shell.rs:418`) with `.plugin(tauri_plugin_dialog::init())` —
   `app/src-tauri/src/shell.rs` (modify, after PRD-01)
6. Project terminal: `terminal.js` sets `window.kanban.connectClaude(projectId)` **before** calling
   `addProjectPanel("terminal", "Terminal", render)`; the drawer panel becomes `addDrawerPanel("terminal", "Terminal",
   render, {tab: "terminal"})`; both re-attach the same per-project session host (`terminal.js:161-181`);
   `connectClaude`: project ≠ current → reject "Switch to the project first"; running `claude-channels` → reveal
   (`"revealed"`); running shell → reveal + status "A shell is open here; close it to start Claude with channels";
   idle → `term_open(project, "claude-channels")` (`pty.rs:10`) → `"started"`; inline `Object.assign` styles replaced
   by PRD-05 tokens/classes — `ui/modules/terminal.js` (modify)

## Interfaces
| Input / output | Validation or consumer | Error states |
|---|---|---|
| `invoke("pick_folder")` → `string \| null` | PRD-05 Add project dialog | wrong window/origin → `Err("not allowed")`; dialog failure → `Err(message)`; cancel → `null` |
| Runtime capability permissions | `core:event:default`, `allow-term-*`, `allow-pick-folder` | any `dialog:*` → test fails |
| `window.kanban.connectClaude(projectId)` → `Promise<"started" \| "revealed">` | PRD-05 panel + welcome | not current project / scope refused / pty error → reject with a readable message |
| Project terminal panel | same host node as the drawer tab | host re-attached; pty survives |

## Acceptance criteria
- [ ] `tauri-plugin-dialog` is the only new crate; `cargo build --locked` works with the committed lock (step 2, NFR-01)
- [ ] Whatever tauri-build generates outside `gen/` for the new command is committed, or nothing if it generates nothing there; `git status` is clean after a fresh `cargo build` (step 3, re-review N6)
- [ ] The capability built by `scope::capability(origin)` lists exactly `core:event:default`, the four `allow-term-*` and `allow-pick-folder`; no `dialog:*`; no static `capabilities/` directory is added (steps 3–4)
- [ ] `pick_folder` from another window label or a non-daemon origin → `Err`, no dialog shown (cargo scope test) (step 5)
- [ ] In the app, Add project → native picker → the PRD-05 preview shows the resolved path (manual Demo step) (step 5, FR-02)
- [ ] Connect Claude from the connection panel opens the project terminal running the channels command in the project folder; the welcome's Connect step turns done once that session subscribes (step 6, FR-05)
- [ ] A second Connect Claude reveals the running session instead of starting another (step 6)
- [ ] `terminal.js` contains no colour or pixel spacing literals; it uses PRD-05 classes/`var(--…)` tokens (step 6)
- [ ] The per-ticket Terminal tab still works (v0.3 behaviour) (step 6)

## Edge cases
| Case | Handling | Priority |
|---|---|---|
| User cancels the picker | `null`; dialog stays on the path field | must |
| Picker opened twice quickly | second call waits or returns `Err("a folder picker is already open")` | should |
| `claude` not on the login shell PATH | the terminal shows the shell's "command not found"; status line links to README troubleshooting | must |
| Project switched while a terminal runs | per-project sessions kept (v0.3); panel shows the current project's session | must |
| Browser mode | `connectClaude` absent → PRD-05 copy path | must |
| Main thread blocked by a modal dialog | command is async; dialog runs off the main thread | must |
